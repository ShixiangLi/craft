Official code default: sequence/fallback short-circuit; parallel runs all children sequentially and requires all-success. Paper section 4.1 instead describes majority voting. This project defaults to code semantics; parallel_policy=majority selects the paper description (strict majority, ties fail).
Expand directly returns its control node's result, without rerunning the parent. Root agent depth is 1, control adds 1, child agent adds 2 from parent agent; max_depth bounds control-node depth.
All model decisions count toward the existing global model-call budget; only actual Crafter actions count as environment steps. Recall does not env.step (official bookkeeping also increments step_id for recall).
max_nodes, max_subgoals, structured JSON, bounded thought strings and max_history_steps are explicit engineering/context adaptations. No hardcoded diamond task tree.
Decision protocol type_first_v1 places type (Think/Act/Expand) before type-specific content. Only Act contains an action name; Think/Expand do not. One model request generates both the category and its content, with no extra classification request. The official src/llm_agent.py first selects Think/Act/Expand through Guidance and then generates the corresponding content; the JSON adaptation preserves this category-first structure, not Guidance candidate scoring or identical generation probabilities. Act/Expand may retain a short, empty-allowed thought for project logging. Root and child expansion remain autonomous, not mandatory. Online parsing rejects legacy action-first responses and misplaced/mixed type fields; old logs remain unchanged and their experiences are historical references, not the current response template.
max_history_steps now defaults to null in code and the example YAML, preserving complete node history at the application layer. Positive windows are explicit resource ablations. Backend context limits still apply. The current ReAct example uses a 16-decision window; a formal comparison must align history settings explicitly.
Adjacent before/after observations and the separately supplied current observation are deduplicated only in the policy input. Stored node traces retain complete transitions, and episodic export preserves the full observation order.
planning_error_policy=node_failure (default) turns expected query-boundary ValueError/RuntimeError and parser ValueError into current-node failure, propagated by the existing tree control flow. It preserves raw logs and planning_failed events without retrying the call or substituting an environment action. abort immediately propagates these errors; model budget exhaustion, user interruption, unrelated programming errors and persistence I/O errors still propagate globally.

Working memory defaults to working_memory_mode=spatial. It uses only the executed action and static-terrain alignment between adjacent public local_map observations to distinguish movement from blockage. Ambiguous movement starts a separate, unmerged coordinate segment. The same segment retains multiple observed landmarks and can report current player-relative deltas; visible static changes replace outdated landmarks. Dynamic objects retain last-seen observations only. max_recall_locations=8 bounds returned locations and reports total/returned counts and truncation. last_seen preserves the initial label-last-observation behavior as an ablation. Neither mode accesses hidden environment coordinates, an unseen global map or oracle subgoal progress; no navigator is added.
Episodic memory reads an explicitly configured, frozen JSONL library. Goals use SentenceTransformer all-MiniLM-L6-v2 and cosine similarity. Same-score examples rotate expand/success/failure/interrupted. Full examples are bounded by character count, unlike the official 5000-token budget.
No Crafter episodic corpus is bundled. The default empty-library run is a ReAcTree+WM mechanism adaptation without episodic in-context examples. Successful environment episodes export all executed agent-node traces (including failure/expand; interrupted labels distinguish unfinished node reports) for later explicit import, not online evaluation-time learning.
episodic_memory_sources explicitly selects completed training run/episode directories and is mutually exclusive with episodic_memory_path. The existing experiment entrypoint invokes modules/reactree/corpus.py before model calls, verifies logged final environment achievements, step order and node/environment trace correspondence, checks train/evaluation seed separation, and writes episodic_memory.jsonl plus episodic_memory.manifest.json inside the new run. Whole-run sources require a complete summary; an explicitly selected episode only requires that episode to be complete and successful. Verification checks saved logs and does not replay the simulator. Training root goals may differ from evaluation goals. ReAct sources retain only whole-root trajectories, labelled react_root_trajectory and subgoals_inferred=false; no subgoal segmentation is inferred.
To prevent indirect seed leakage, the builder currently rejects ReAcTree training sources collected with EM enabled and a nonempty episodic_memory_path or episodic_memory_sources, even when the source episode's own seed is disjoint: its prior examples may include evaluation seeds. Sources collected with EM disabled are exempt. The supported procedure collects training experiences without an existing episodic library, then freezes them for evaluation.
The effective config stores the resolved frozen path and clears sources; metadata/manifest preserve source selections, training tasks, seeds and file hashes. There is no automatic scan or import of old outputs. Direct nonempty episodic_memory_path libraries also require source.seed per record and reject unknown/overlapping declared seeds before evaluation, but do not independently verify the full experience lineage; a self-declared episode_success flag in an external library is not independent verification of its original logs. This does not provide the builder's source-validation guarantee. Oversized complete examples are skipped, not silently summarized or truncated.
Recommended procedure: collect successful short-task node experiences on independent training seeds, then change the same config back to diamond and disjoint evaluation seeds and select the completed training sources. No additional launcher or config copying is required. No completed ReAcTree corpus is automatically available at present; an old successful ReAct diamond root trajectory is too large for the default 20000-character example budget and is not an effective default bootstrap.
Rules and primitive game example content are reused from prompts/common/crafter_rules.txt and prompts/react/examples.txt without editing those files. Only the shared examples' Response JSON is mechanically converted to the current type-first Act format when injected; observations, actions and thoughts are unchanged, and no decomposition demonstrations are added. These project-authored prompts adapt the mechanism; they are not copied official WAH-NL/ALFRED assets.

The original experiments are WAH-NL and ALFRED, not Crafter. Table 1 Qwen2.5-72B: ReAct 26%, ReAct+WM 31%, ReAcTree 48%, ReAcTree+WM 61% goal success. Implementation tests do not reproduce these scores.
