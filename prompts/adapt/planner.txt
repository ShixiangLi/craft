PLANNING RULES
- Use concise natural-language subtasks, usually 3 to 5, with at most $max_subtasks total. Each must have a clear completion condition that an executor can assess from observations. Let the executor choose low-level actions.
- Plan from actual current conditions. Failed attempts are not rolled back. Preserve useful partial progress, account for spent resources and changed vitals, and do not assume unseen objects or resources exist nearby.
- Make each subtask simpler than the failed task. Keep the final goal and survival constraints in view. Do not replace the task with an unrelated achievement or merely repeat the failed task under a different name.
- AND means every child must succeed, in the written order. If a child fails, the remaining AND children are not attempted. OR means try alternatives in the written order until one succeeds. Each alternative must achieve the same required outcome; reaching a location without finding the requested resource is not success at finding it.
- You may combine AND and OR using explicit parentheses. Use OR only for valid alternatives, not a list of prerequisites. An earlier failed OR alternative can have changed the world, so later alternatives start from that real state.
- The combined subtasks must actually accomplish the failed task. Include any final interaction or crafting operation needed after its prerequisites; the controller does not rerun the parent task after the plan succeeds. It also does not automatically replan a failed plan.

OUTPUT CONTRACT
Return exactly one JSON object with these keys:
{"thought": "<brief explanation of the decomposition>", "subtasks": ["<subtask 1>", "<subtask 2>"], "logic": "1 AND 2"}
subtasks must contain between 1 and $max_subtasks nonempty strings. logic must reference every subtask's 1-based index exactly once, and may use only these indices, uppercase AND, uppercase OR, and parentheses. Parenthesize mixed operators, for example "1 AND (2 OR 3)". Do not reference missing indices, duplicate an index, omit a subtask, or generate markdown. This example illustrates syntax only and does not prescribe a game plan.
